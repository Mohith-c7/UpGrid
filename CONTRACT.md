Monorepo root: /mnt/user-data/outputs/upgrid
- `server/`  Express + TypeScript + PostgreSQL (pg, zod, jsonwebtoken, bcryptjs, helmet, cors, express-rate-limit). Deploy target: Render (Singapore).

## Validation rules (identical in server zod and app zod — put in `server/src/validation.ts` and mirror in `app/src/lib/validation.ts`)
- email: trim, lowercase, max 254, regex `^[a-z0-9._%+-]+@[a-z0-9-]+(\.[a-z0-9-]+)*\.[a-z]{2,}$`, no `..`, no leading/trailing dot in local part. If domain is gmail.com or googlemail.com: local part (before any +tag) must be 6–30 chars of a-z 0-9 and dots, no leading/trailing/consecutive dots, must not start with a digit-only... (digits allowed but not purely dots); treat common typos `gmial.com, gmai.com, gamil.com, gmail.co, gmail.con, gmal.com, gmil.com, hotmial.com, yahooo.com` as errors with message "Did you mean gmail.com?". Normalize googlemail.com→gmail.com for uniqueness; for uniqueness also strip dots and +tag for gmail.
- phone (India mobile): accept input with spaces, dashes, `+91`, `91` (when 12 digits) or leading `0` (when 11 digits); normalize to exactly 10 digits; must start with 6–9; reject all-same digits (e.g. 9999999999), 1234567890, 0123456789; store as 10-digit string; display `+91 98765 43210`. Reject letters. Show live error text: "Enter a valid 10-digit mobile number starting with 6–9".
- password: 8–64 chars, at least one letter and one digit, no spaces at ends.
- name: 2–80 chars, letters/space/.'- only (unicode letters allowed), collapse spaces.
- registration number: 5–20 chars, A-Z0-9/-, uppercase normalized.
- CGPA: number 0–10 (or 0–scale), max 2 decimals; percentage fields 0–100 max 2 decimals; active backlogs integer 0–50; gap years integer 0–10; batch year 2020–2040; semester 1–12.
- URLs: https only, max 300; linkedin must be host linkedin.com or *.linkedin.com; github must be github.com host.
- All strings trimmed, length-capped; reject control characters. Dates ISO-8601 UTC in API.

## Roles
`student`, `officer`. Officer self-signup requires `inviteCode` equal to env `OFFICER_INVITE_CODE`. Single-university MVP but every table has `tenant_id uuid` (default tenant seeded) and every query is tenant-scoped.

## API (base path `/api/v1`, JSON, `Authorization: Bearer <accessJWT>`). Errors: `{ "error": { "code": string, "message": string, "fields"?: { [field]: string } } }` with proper HTTP status (400 validation, 401, 403, 404, 409, 422, 429).
Auth: POST /auth/register {name,email,phone,password,role,inviteCode?} → {user,accessToken,refreshToken}; POST /auth/login {email,password}; POST /auth/refresh {refreshToken} (rotation); POST /auth/logout; GET /me; PATCH /me {name?,email?,phone?} (same validation as register; 409 EMAIL_TAKEN/PHONE_TAKEN; role/other fields rejected 400); POST /me/change-password; DELETE /me (soft delete).
Profile (student): GET /profile → full profile + `completion {percent, items:[{key,label,done,why}], nextStep}`; PUT /profile (partial patch of: identity{registrationNumber,preferredName}, academics{university,department,program,batchYear,semester,cgpa,cgpaScale,tenthPercent,twelfthPercent,activeBacklogs,gapYears}, contact{city,state}, links{linkedin,github,portfolio}, skills[], preferences{roles[],locations[],workMode,relocate}); GET/POST/DELETE /profile/resumes (label + https url, one marked default, max 5); each field carries `verification: 'unverified'|'verified'|'student_confirmed'` managed server-side (officer verifies via POST /students/:id/verify {fields[]}). Editing a verified academic field resets it to unverified.
Drive compensation: fixedLpa > 0 is required to publish; variable/bonus/ESOP optional; breakdownProvided=false means the app shows 'Breakdown not provided'.
Drives: GET /drives?q=&status=open|closing|closed&eligibility=eligible|not_eligible|pending&sort=closing|newest|package&saved=1&cursor=&limit= → {items,nextCursor}; each item: id,company{name,logoUrl,industry,verified},role,workMode,locations[],ctc{fixedLpa,variableLpa,bonusLpa,esopNote,breakdownProvided,kind:'annual'|'stipend_monthly'},deadline(UTC),status,eligibility{status,reason},saved,applied. GET /drives/:id adds JD, requirements, rounds[], questions[], policyNote, contact, lastVerifiedAt, dataSharedPreview. Officer: POST /drives (draft), PUT /drives/:id, POST /drives/:id/publish (completeness gate → 422 listing missing items), POST /drives/:id/close, POST /drives/:id/duplicate, GET /drives/:id/eligible-count (+ per-reason counts), GET /drives/:id/applicants?status=. Deadline edit cancels/recreates reminders. Closing time must be in future at publish.
Questions types: short_text,long_text,number,date,single_select,multi_select,yes_no,url,declaration; fields: id,label,type,required,options[],maxLength,helpText,saveToProfileKey?(optional).
Saved: PUT/DELETE /drives/:id/save.
Apply: POST /drives/:id/application/preview → {mapped:[{key,label,value,source,verification,sharedWith}], conflicts[], missingProfileFields[], questionsToAsk[], resume options, deadline, serverNow, canApply, blockedReason?}; POST /drives/:id/apply {idempotencyKey(uuid), resumeId, answers{qid:value}, declarationsAccepted:true, saveToProfile?:[keys]} → 201 {application:{id,reference,submittedAt}}; duplicate/replay with same key returns same receipt (200); different key but already applied → 409 ALREADY_APPLIED; past deadline (server time) → 422 DEADLINE_PASSED; not eligible → 422 NOT_ELIGIBLE; missing required answers → 400 with fields.
Applications: GET /applications (student), GET /applications/:id with events timeline; POST /applications/:id/withdraw (only before screening); POST /applications/:id/respond {decision:'accept'|'decline', note?} (student, only when status is offer_issued; appends event, notifies drive owner/officers, idempotent: same decision again → 200 {replayed:true}; GET /applications/:id returns canRespondToOffer); officer POST /applications/:id/status {status,note} allowed statuses: submitted,screening,assessment,interview,selected,offer_issued,offer_accepted,offer_declined,rejected,withdrawn,joined (transition rules enforced; events append-only).
Students (officer): GET /students?q=&branch=&batch=&verified=&cursor=; GET /students/:id; POST /students/:id/verify.
Eligibility engine `server/src/eligibility.ts` deterministic pure function; drive.rules {minCgpa,min10th,min12th,maxActiveBacklogs,maxGapYears,allowedDepartments[],allowedBatches[]}; result {status:'eligible'|'not_eligible'|'pending',reasons:[{criterion,required,actual,met,source,verification}]}; `pending` when needed data missing or academic field unverified-and-policy-requires-verification(tenant setting default: unverified counts as pending only if missing; keep simple: missing→pending).
Notifications: GET /notifications, POST /notifications/read {ids|all}, GET /notifications/unread-count; GET/PUT /reminder-settings {t60,t30,t15 booleans default true, push,inApp,quietHours{enabled,start:'22:00',end:'07:00'}} + POST /reminder-settings/reset; POST /devices {expoPushToken,platform}; DELETE /devices.
Reminder scheduler: table `scheduled_reminders(id, drive_id, user_id, kind t60|t30|t15, fire_at, status pending|sent|cancelled|skipped, unique(drive_id,user_id,kind))`. In-process worker polls every 30s with `FOR UPDATE SKIP LOCKED`; sends in-app notification + Expo push (https://exp.host/--/api/v2/push/send) if token & enabled; never sends after deadline; suppressed after apply/withdraw-not-needed/drive close; quiet hours defer to in-app only; skip reminders whose fire_at already passed when drive published late (only future ones scheduled). Reminders created at publish for every eligible-or-pending student; also when a student's profile changes to eligible. Copy exactly per PRD 5.5.
Announcements: POST /announcements (officer, optional driveId audience) → in-app notifications to audience; GET /announcements.
Officer dashboard: GET /officer/dashboard → {openDrives,closingToday,applicationsToday,pendingVerifications,upcoming[]}.
Misc: GET /health, GET /time (server UTC now), rate limit auth routes (10/min/IP) and global (300/min).
Seed (`npm run seed`): 1 tenant, 1 officer (officer@placement.demo / Officer@123), 3 students (incl. complete profile, partial profile, ineligible), 8 realistic but clearly FICTIONAL demo companies (no real brand logos; initials fallback), drives in varied states (open, closing in 40 min, closed, draft). Never claim integrations are live (ERP/SSO are NOT built; state it in README).

## Integrations (migrations 003-009; full shapes in `server/docs/integrations-api.md`, setup in `server/INTEGRATIONS.md`)
Every integration is env-driven and degrades to a clear "feature off": the app MUST read `GET /api/v1/config` (public) at start -> `{features:{googleLogin,emailVerification,fileUploads,turnstile,requireVerifiedEmail,...other modules}, googleClientIds:{web?,android?,ios?}, turnstileSiteKey?, limits:{resumeMb:5,photoMb:2,logoMb:1,documentMb:5}}`.
- User object (auth responses, `/me`) adds `emailVerified`, `authProvider:'password'|'google'`, `hasPassword`; `phone`/`phoneDisplay` may be `null` (Google sign-ups).
- Rule change: `submitted` -> `assessment` and `submitted` -> `interview` are allowed (status route and schedule).
- Email OTP (6 digits, sha256+salt, 10 min, 5 attempts, 60 s resend, 5/h per email, 20/h per IP): `POST /auth/email/send-verification` (auth) -> `{ok,expiresInSeconds,resendAfterSeconds}` | `{ok,alreadyVerified}`; `POST /auth/email/verify {code}` (auth) -> `{ok,user}`; codes never in responses. Errors `INVALID_CODE`, `CODE_EXPIRED`, `TOO_MANY_ATTEMPTS` (429), `RESEND_COOLDOWN` (429, `error.retryAfterSeconds`), `RATE_LIMITED`, `EMAIL_NOT_CONFIGURED` (503).
- `POST /auth/forgot-password {email}` always `200 {ok:true,message}`; `POST /auth/reset-password {email,code,newPassword}` -> `{ok:true}` (revokes all refresh tokens).
- `POST /auth/google {idToken, acceptTerms?}` -> `{user,accessToken,refreshToken,isNewUser,needsPhone}`; new users are students only; `400 TERMS_REQUIRED` until `acceptTerms:true`; errors `INVALID_GOOGLE_TOKEN`, `GOOGLE_EMAIL_UNVERIFIED`, `GOOGLE_ACCOUNT_CONFLICT`, `GOOGLE_LOGIN_NOT_CONFIGURED` (503).
- Apply gates: `403 EMAIL_NOT_VERIFIED` (when `features.requireVerifiedEmail`), `403 PHONE_REQUIRED`; preview adds `blockedCode`. Profile completion has a `phone` ("Mobile number") item.
- Turnstile: `turnstileToken` (body) or `X-Turnstile-Token` on register/login/forgot-password/google when `features.turnstile`; `400 CAPTCHA_FAILED`, `503 CAPTCHA_UNAVAILABLE`.
- Files (R2): `POST /files/presign {purpose:'resume'|'photo'|'company_logo'|'document',fileName,contentType,size}` -> `{fileId,uploadUrl,method:'PUT',headers,expiresIn:600}`; PUT bytes to `uploadUrl`; `POST /files/:id/confirm` -> `{file}`; `GET /files/:id/url` -> `{url,expiresIn:300}`; `DELETE /files/:id`; 20 ready files per user; `503 FILE_STORAGE_NOT_CONFIGURED` when off. Resumes: `POST /profile/resumes {label,fileId}|{label,url}`, resume objects have `fileId` and `kind:'file'|'link'`; officer `GET /applications/:id/resume-url`; applicants CSV gains `resumeKind`; `company.logoFileId` on drive create/update sets `company.logoUrl`.
- Email notifications (best effort, after commit): schedule created/updated, offer response (to officers), ticket replies; user switch `email` in `GET|PUT /reminder-settings` (default true).
